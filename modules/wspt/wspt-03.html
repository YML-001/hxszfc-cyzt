用户与角色是一人多角色关系，变更留痕。保存后即时生效：用户下次请求即按新角色鉴权， 正在进行的会话无需重新登录即可看到菜单变化。

角色标识角色名称分类绑定用户 授权菜单可访问应用数据范围状态操作

角色应用边界限定该角色可访问的应用集合——即便菜单授权里勾了某个菜单， 若该菜单所属应用不在角色的应用边界内，菜单仍不出现。这是权限链路的最后一道闸。

功能权限链路固定为：用户 → 角色 → 菜单/按钮 → 权限资源（method_name / api_url）→ 应用（R-K2）。 本页配置的是链路中的角色 → 菜单/按钮一段；接口权限资源的登记在 菜单与权限资源。

第 3 档的落地要求 性能与正确性都取决于这一条
正确写法 WHERE ancestors LIKE '0,100,200%' OR id = 200
错误写法 递归查询子部门 （层级深时性能急剧下降，且易漏节点）

子树查询使用 ancestors 路径 LIKE 匹配（当前部门 ancestors ＋ 当前部门 id 前缀）或 id 等于当前部门， 禁止递归查询。部门层级变动时必须同步维护 ancestors， 否则第 3 档判定会漏掉整棵子树。 去组织树检查 ancestors
