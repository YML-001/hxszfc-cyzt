调试台有个跟别的服务不一样的地方：消息接口一发就真的会有人手机响。 所以联调环境做了拦截——除非填的是白名单里的测试号码，否则短信不会真发出去， 只在响应里展示「本该发出的内容」。 回执、上行这类由三方推过来的接口，用「模拟三方回推」自己造报文触发， 看平台的解析与回写对不对。

请求头
当前填的 13800138000 在测试号码白名单里，会真实发出。 换成任何其他号码，联调环境只回显内容不真发。 这条规矩是有来历的——去年联调时有人拿真实业务数据跑批量接口， 给 200 多位群众发了「测试短信」，第二天接了一上午投诉电话。

requestId 是幂等键，同一个 ID 重复提交只会发一条。 业务系统重试、用户狂点提交按钮，靠的都是这个字段兜底。 没传的话平台会用「模板 + 号码 + 业务号」组合算一个，但不如自己传可靠。

调试台在这里帮你发现了一个真问题：响应里 billingCount 返回 1， 但内容实际 108 字，按 70 字规则应该计 2 条。 核对后确认是计费预估逻辑把标点当成半角算了。 这个 bug 不影响实际扣费（以通道账单为准）， 但会让费用测算偏低，已登记修复。 这就是「仅校验不发送」这个按钮存在的意义—— 在花钱之前先看清楚要花多少。
